# Git

Simple rule: if I ask for a git operation, do it. If I don't ask, don't do it.

Never run git operations on your own initiative — no commits, pushes, resets, rebases, merges, tags, or other history-altering or remote-affecting commands unless I explicitly ask for them in this conversation. Don't ask "should I commit?" after finishing work; just stop.

When I do ask ("commit", "push", "commit and push", etc.), proceed without asking for re-confirmation. Use your judgment on commit message and granularity.

Read-only commands (`git status`, `git diff`, `git log`, `git show`, `git branch`) and staging (`git add`) are fine anytime.

# Response style

Think carefully and thoroughly, but keep responses short and direct.

- Answer the question, nothing more.
- No preamble, no restating the question, no "Great question!"-style filler.
- No closing summaries ("Let me know if you need anything else" etc.).
- Prefer a single sentence or short bullet list over a long paragraph.
- Only include code, detail, or explanation when it is genuinely needed.
